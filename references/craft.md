## 1. "有工艺感"（crafted）意味着什么

获得认可的图共有五项特质。

1. **一个你真能造出来的实物。**读者一眼就能叫出它的名字：一台试验台、一支指示表（dial indicator）、一个五斗柜、一台龙门绘图机、一把锁。它是为主题发明的，绝非照参考描摹。
2. **许多细小而精确的零件。**一幅好的内联图有 30–60 个实体（solid）和 300–500 条路径（path）。零件确实更多的主角题材能承载远多于此：台式电脑约 85 个实体，Raptor 约 270 个实体、分布在 478 个按深度排序的元素中。每个零件都依托另一零件、与邻件对齐、并各有职责。密度来自结构（底脚（feet）、导轨（rails）、限位、轴套（bushing）、旋钮），而非纹理。
3. **体积感（volume）。**零件有真实厚度，侧面以四档色调着色，顶面更亮，斜切面能接住光，底下还有一圈柔和的光晕（halo）。
4. **克制（calm）。**0.6 px 细线与收敛的配色。唯一一处点亮的强调告诉眼睛该看哪里。运动带缓动、且慢到足以跟上。
5. **真实（truth）。**读数显示实时且正确的数字，运动遵循真实模型：弹簧有真实刚度，尺寸与阈值都属实。

## 2. 反模式（Anti-patterns）

以下每一条都被评审者否决过，所以不要这样做：

- **抽象堆叠。**用悬浮的板、厚板或瓦片代表"层"，抽象到读不出任何东西。需要"层"时，把它们做成抽屉、架上的托盘、导向立柱上的板，或卡片座里的卡片。
- **一整块素平大板。**只带几条线的大表面太扁平、太乏味。把它拆成底板（base plate）、滑座（carriage）和零件；加一道凹槽、螺丝、一条标尺和一块铭牌（label plate）。
- **蓝图式装点。**指引线、带数字的气泡、尺寸箭头、剖面线、虚线隐藏边与悬浮标签属于图例和说明文字，不属于图本身。
- **悬空停住的线。**扇形指引、在零件前就结束的连接线，或在轮廓角之前停住的折痕。每条线都必须落在某个东西上。
- **线框。**能看透、露出后侧棱边的盒子。
- **满图彩色。**保持单色，除非颜色本身是主题：仅一处点亮的强调，外加只用于颜色通道的真 RGB。流体默认不算颜色：视油镜里的油、水箱里的水、管路里的冷却剂都是图自身墨色的淡染，`--no-webgl` 回退绘制的淡染与着色器一致。一个盲测台在整幅灰调图里把油画成高饱和橙色，而它的回退油却是灰的。
- **图内文字。**至多允许一个微小的镌刻标签（面上的 `FaceText`）。其余一切放进卡片角落、图例或说明文字。
- **照抄参考。**从参考取氛围与质感，然后自行发明物件。
- **生硬的指针跳变。**零件直接吸附到光标。一切都要缓动。
- **管道穿管道。**在第一版 Raptor 上，所有者放大后发现线缆与管线穿过主导管、彼此穿插，"这毫无道理"。1× 下看着没问题。每根管、每条缆都与其自身连接点之外的一切保持间距，每处交叉都按真实深度顺序绘制，且 `kit/audit.mjs` 能证明这两点（第 8 节"间距与交叉"）。
- **戛然而止的纹理。**同一张特写上，燃烧室的螺栓圆点阵列在表面正中戛然停住，钟形段与喉部被着色成平坦色块拼成的色阶阶梯（staircase）。两处读起来都是坏的。所有者的原话：如果纹理必须结束，"我们宁可让它们在末端淡出，也不要瞬间截断"。曲面要平滑着色，让纹理终止于真实边缘或淡出（fade）（第 8 节"曲面上的着色与纹理"）。
- **突现或被截断的着色器。**第一版 Raptor 的羽流在各阶段之间瞬间变色，"像被剪掉一样"，还有一团光晕在画布边缘以直线告终。每个着色器项都乘一个包络，并在任何边界之前归零（`webgl.md` 第 7 节）。
- **平面上也会戛然而止的纹理。**同样的毛病又出现在后来一幅图的盒体上，那里没有曲面规则可管：油箱焊缝距每个圆角内缩 6 单位、歧管面线内缩 4、一排淡刻度悬浮在没有标尺承托的裸机座上、散热肋在两端距缝弧 2 单位停住，还有一根软管的编织纹画成沿中心线的虚线描边——沿软管方向以两条笔直硬边告终、在每个分块接缝处断裂。盒体上的缝沿可见棱角从边到边环绕（`k.sideSeam`）；肋在同一 `s` 处终止于缝上（`ribsOf(…, { seams: true })`）；刻度悬挂在标尺条（ruler strip）的边缘上；管上的纹理来自 `tubePieces(…, { rings })`。`node scripts/lines.mjs page.html` 会对每个未触及任何东西的线端判失败（`verify.md`"线端"）。
- **替身形状。**为了让审计安静，某建造者为五份相互重叠的杆副本各在末端记录了一个 0.45 厚的圆盘，又为第二根被画成沉入其缸盖的杆记录了一条细条。审计通过了，对两根杆只字未提，而点亮的杆移动时轮廓每 12 单位就出缺口。记录所画之物的真实形状；审计的替身检查会让记录形状覆盖不足其绘制 60% 的元素失败。从密封套（gland）滑出的杆就是一根杆（第 3 节"从密封套伸出的杆"）。
- **贴上白底的深色主题光晕。**所有者把浅色定为所有站点图的发布主题，七幅建在深色底板上的着色器图不得不转换。把深色光晕再加深，得到的是"红墨水烟雾"（Raptor 的浅色羽流）。还带来画成轮廓线的火焰、看着像污点的火花、橙红色的冷却玻璃、灰色的淡出，以及火熄灭时反而愈发沉重的腔体。在纸面上，亮要靠饱和度与更深的物理底色来读出（第 7 节，及 `webgl.md` 第 8 节）。
- **凭眼睛修一个特写。**调一个画师键或微移一个路点，直到某张截图看着对了，会弄坏另一帧或另一主题。Raptor 手工设定的键在 1× 下看着没问题，却有 323 个深度顺序问题。先测量（第 8 节"间距与交叉"），再看。

## 3. 部件词汇表与配方

`P` 是投影，`k` 是工具包，如 `import * as k from "./iso-kit"`。高度以世界单位计，z 轴向上。按所列顺序绘制每个配方的实体。

### 带底脚的底板
```js
const PLATE = { x: -128, y: -64, w: 262, d: 128, r: 8 };
halo:  `<path class="iso-halo" d="${k.haloOf(PLATE, -17, 12, P)}"/>`
feet:  for (const [x, y] of byDepth(k.corners(PLATE, 22))) {
         k.cylinder(x, y, 7, -17, 1.6, P, 28)            // flange, tone lo
         k.cylinder(x, y, 5.4, -15.4, 3.4, P, 28)        // foot, tone mid
       }
slab:  k.slabOf(PLATE, -12, 12, P, 8, 1.6)                // tone mid, bevel 1.6
groove: k.planOutline(k.insetPlan(PLATE, 5), 0, P)         // line lo
screws: k.corners(PLATE, 10) → k.ring(x, y, 2.2, 0, P, 16) (line lo) + dots size .5
```
用 `byDepth = (pts) => [...pts].sort((a, b) => k.depthOf([a[0], a[1], 0], P) - k.depthOf([b[0], b[1], 0], P))` 对底脚排序。

### 标尺条与铭牌
```js
const strip = { x: -110, y: PLATE.y + PLATE.d - 15, w: 230, d: 7, r: 1 };
k.slabOf(strip, 0, 0.6, P, 3)                                   // tone lo, crease none
const t = k.topTicks(strip.x + 4, strip.x + strip.w - 4, 4, 5, strip.y + 0.8, 0.6, [2, 3.6], P);
t.minor → line lo, t.major → line mid
label plate: k.slabOf(plan, 0, 0.8, P, 4) + k.planOutline(k.insetPlan(plan, 1.6), 0.8, P) (faint)
             + three k.lineOnTop rule lines of different lengths (lo, { free: true }) + two screw dots
```
刻度只存在于标尺条或表盘上，并扎根于其边缘：`topTicks` 让每根刻度从 `edge` 长出，所以把 `edge` 放在条带边缘上（或距边缘 1 单位以内）；`sideTicks` 把刻度悬在 `top` 之下，所以传入表盘的上边缘，而不是其下方 2 单位处。裸板上的一排刻痕是两端悬浮的纹理。铭牌的刻线代表印出的文字，因此是唯一允许一条线停在裸面上的地方：传 `free: true`，线检查就知道这是有意的。

### 盒体上的接缝、焊缝与饰线
```js
const seam = k.sideSeam(TANK, 14, P, 6);                         // visible near half of the plan at z = 14, round the corners
k.solidSvg(k.slabOf(TANK, 6, 98, P, 6, 1.2), { tone: "mid", inner: k.lineSvg(seam, { tone: "faint" }) })
```
盒体上的接缝、焊道、环带或盖沿线绕过可见棱角、恰好终止于竖直轮廓边，如同圆柱上的 `sideArc`。传入板件自己的 `steps`，让缝跟随同样的面片；把它作为 `inner` 传入，让线端压在轮廓之下。只属于一个面的线（加强筋、面板接缝）贯穿整面、从边到边：`segment([x, y, z0], [x, y, z1])`，其中 `z0` 与 `z1` 是该面的底与顶，绝不是 `z0 + 3`。开槽与散热缝（vent）是闭合轮廓（薄圆角平面的 `planOutline`，或面平面上的同样形状），因此根本没有端点。绝不要把线从棱角内缩几单位：4× 下它读作一条戛然而止的纹理。

### 从密封套伸出的杆
活塞杆、测杆（plunger）或滑块——凡可见长度随移动变化者——是一根杆，按全长（可见段加行程）一次性构建，并把密封套内部的部分裁掉：
```js
const ROD = G.rodOut(F, gland, tip, r, P, { stroke });           // F.a points out of the gland
svg = `<clipPath id="rod"><path data-hold d="${ROD.clip}"/></clipPath><g clip-path="url(#rod)">${k.solidSvg(ROD.paths, { lit: true })}</g>`
R.put({ ..., move: G.mul3(F.a, stroke), svg, shapes: [R.solid(A.slide(F, gland, tip, r, { name: "rod" }))] })
live: el.setAttribute("transform", `translate(${dx} ${dy})`); holdStill(el, [dx, dy])   // dx, dy: the item's screen offset this frame
```
`rodOut` 返回从 `gland − stroke` 到 `tip` 的杆路径，以及一个从密封套面覆盖到 `tip + stroke` 的裁剪。裁剪路径带有 `data-hold`；移动该元素的代码以相同的屏幕偏移调用 `holdStill(el, [dx, dy])`，这会让裁剪朝反方向移动，于是杆滑过时密封套面保持不动。同一辅助函数在其元素反向移动时把杆收回密封套（加载缸）。在密封套上画一圈淡密封环（在密封套面处 `circleOf`，半径 `r + 0.4`）。用 `A.slide` 记录它，审计由此以从密封套面拉伸杆（而非平移）的方式摆姿态，因此间距、深度与实体检查在每一帧看到的都是真实的杆。绝不要用重叠副本伪造伸出：每份副本的点亮相在下一份副本的填充开始处停住，移动时轮廓每隔几单位就出缺口。

### 导轨、限位块与滑座
```js
rails:  for y of [-20, 15]: k.slabOf({ x: 2, y, w: 122, d: 5, r: 1 }, 0, 3, P, 3, 0.4)   // mid
stops:  k.slabOf({ x, y: -23, w: 5, d: 46, r: 1.2 }, 0, 7, P, 3, 0.5) + 2 screw dots on top
carriage (built at x = 0, moved with translateAlong):
        k.slabOf({ x: -28, y: -24, w: 56, d: 48, r: 3 }, 3, 5, P, 5, 0.6)
        bushings: small slabs at the four corners, taller than the plate, with screw dots
        rivets: a row of 0.4 dots along the front edge
        handle: a small neck slab plus a knurled cylinder on the front face
```

### 立柱、轴环、线夹（clamp）与拇指螺钉
```js
k.cylinder(px, py, 5, z0, 4, P, 28)              // collar
k.cylinder(px, py, 3.2, z0 + 4, h, P, 28)        // post, crease none
k.sideArc(px, py, 3.2, z, P, 16)                 // faint seam rings on the post
k.slabOf({ x: px - 7, y: py - 7, w: 14, d: 14, r: 2.5 }, zc, 12, P, 4, 0.6)   // clamp block
thumb screw: a 2.8 × 3 neck slab from the clamp face + k.cylinder(r 2.6, h 6) + k.knurl(..., 18)
```

### 带指针的滚花（knurl）旋钮
```js
k.cylinder(cx, cy, 6, z, 4, P, 32)                          // mid
k.knurl(cx, cy, 6, z, z + 4, 36, P)                         // line lo
k.lineOnTop([cx - 3, cy], [cx + 4.6, cy], z + 4, P)         // pointer, line hi
```

### 绕杆的螺旋弹簧（coil spring，为画师顺序拆分）
```js
const c = k.coil(xFrom, xTo, [rodY, rodZ], 4.2, 6, "x", P);
c.back  → line lo, drawn BEFORE the rod
rod     → k.slabOf({ x, y: rodY - 2, w, d: 4, r: 1.8 }, rodZ - 2, 4, P, 3)
c.front → line mid, drawn AFTER the rod
```
弹簧压缩时每帧通过改变 `xFrom`/`xTo` 重建螺旋线。这很便宜。

### 指针量表（dial gauge，表面朝上）
```js
k.cylinder(x, y, R, z, 10, P, 64, 0.8)                       // puck, tone hi, crease lo
k.knurl(x, y, R, top - 3.4, top, 84, P, 0.3)                 // knurled bezel band, lo
k.sideArc(x, y, R, top - 3.4, P, 40)                         // band seam, faint
k.ring(x, y, R - 2.2, top, P, 64)                            // bezel ring, lo
const t = k.radialTicks(x, y, R - 3, 50, 5, top, [1.3, 2.8], P)   // minor lo, major mid
crown: two small slabs on the +x side; lug: a slab joining the arm
needle: k.lineOnTop(tail, tip, top + 0.2, P), tone lit, stroke-width 1.1, rebuilt per frame
hub: k.ring(x, y, 1.6, top, P, 16)
```

### 灯、探针与压指
它们都是圆柱堆叠：壳体、盖环、轴环、杆身、垫块。缝环来自 `sideArc`，锁紧螺钉是一块小板加上侧面的圆柱头。

## 4. 色调

| 元素 | 色调 |
|---|---|
| 底板、底脚、地面 | `lo` |
| 结构：立柱、导轨、框架、滑座、壳体 | `mid` |
| 主题：被解释的对象 | `hi` |
| 读者此刻应注视的零件 | `lit`（仅一个） |
| 凹槽、内缩轮廓、地面网格 | `faint` |
| 次刻度 | `lo` |
| 主刻度 | `mid` |
| 零位标记、指针线 | `hi` |
| 螺丝与铆钉 | 0.4–0.55 的 `mid` 圆点 |
| 折痕（顶/侧交界） | `faint`（默认），`hi` 零件上用 `lo` |

带 `lit` 的 `Solid` 会获得白色描边与更亮的顶面。用于运动中的主体、测杆或被选中的抽屉。

## 5. 画师顺序（painter's order）

- 先画底座，再画依托其上的一切。
- 同一层级内按 `depthOf(centre, P)` 升序排序：先远后近。
- **拆分包裹件。**绕滑座的弹簧或框架：先画后半，再画内部零件，再画前半。试验台里：后框架杆 → 带后螺旋半段的杆 → 滑座 → 玻璃 → 前螺旋半段 → 前杆 → 量表。
- **运动零件**按其在顺序中的槽位绘制，包在带动它们的 `<g transform>` 里。若一个运动零件可能绕到同一邻居的前面和后面，就拆分该邻居或限制运动，让顺序永不改变。
- **立在阶梯面上的物件。**安排台阶顺序让更高者更靠后。这样停在较低台阶上的探针就不会被前方更高者遮住。
- 穿过水平件的竖直件（穿过线夹的立柱）围绕水平件分下、上两段绘制。
- **裁剪切线就是一条边。**凡裁剪使一个零件相对于另一个结束之处（进入其环圈的拖链段、密封套处的杆），让裁剪截面与结合面齐平，并沿切线画一条随裁剪移动的描边边线（`data-clip`）。等离子切割器上，一段缆的裁剪截面越过了结合面：该段缆的顶面与槽杆被画进环圈空腔 26 单位、终止于一条无描边的竖直切线，这就是一条悬空停住的线。重排画师键也修不了它：环链的端面确实在该段缆之后。
- **稠密图形靠几何定键。**超过几十个重叠零件后，手工设定的偏置（bias）会互相打架。给每个元素真实形状，让 `kit/audit.mjs` 测量两元素重叠处哪个表面更近，然后 `orderKeys` 把每个键抬到恰好满足每一对（`kit.md` 第 12 节）。它满足不了的是互锁（interlock）的一对，那需要拆分。第一版 Raptor 的手工键留下组装态 190 对、分离态 133 对画反；测量键把两者都归零。
- **交叉按分块排序。**管道或线缆画成 `tubePieces` 分块，每块是独立元素、有各自深度，于是一条线可以在一个零件前、下一个零件后。两线在屏幕上交叉处，更靠近相机的分块后画；只有当两块不在其他地方又互绕到背后时，交叉才可排序，所以要在交叉处打断长分块（`breaks`）。

## 6. 相机与构图

- 默认相机：方位角 45°、仰角 30°。旋转方位角（35–60°）让承载机构的面朝向观察者。试验台用 57° 展示长边。抬高仰角以看清开口内部：水波槽用 44°，让水面与槽底的纸都能读到。
- 用 `fitProjection(boxCorners(...) ∪ tallest points, width, height, { pad: 24–34, azimuth })` 拟合。典型 viewBox 为 600 × 340–380。
- 物件占卡片约 55–65%。四周留白、不要让它碰到角落标签，并保持一组图的尺寸一致。
- 在手机（390 px）上检查仍可读。零件太小时，在带 `overflow: hidden` 与负边距的卡片内把 SVG 放大到约 110–118%，如试验台示例中的 `stretch.css` 所做的那样。

## 7. 主题

`ISO_CSS` 在 `.iso` 上定义令牌（token），深色为默认，`.iso[data-theme="light"]` 为浅色。每个填充与描边都读取令牌，所以一个主题只是一套令牌。调整方式：

- **纸色**（`--anatomy-paper`）与卡片颜色相同，因此填充能遮住背后的东西而不显成补丁。
- **明暗。**从最暗（0，背光面）到最亮（3）共四档。保持彼此接近：亮度相差约 3%。
- **线条。**深色模式下 `hi` 接近白色、`faint` 仅略高于纸色。浅色模式反转这一点。
- **光晕。**底座下方一团模糊的深色填充：深色模式下浓，浅色模式约 30%。

**浅色随版本发布。**isometrics 站点上的每幅图都是浅色，着色器图也不例外。先设计浅色，在代价低之处保持深色可用。那七次着色器转换对绘图教了这些：
- **每个颜色都是令牌。**硬写进图的 CSS 或其着色器的颜色是一个迟早发作的主题 bug。给它浅色值与深色覆盖（`.x { --x: … }`，然后 `.iso[data-theme="dark"] .x { --x: … }`）。着色器需要同一颜色时，从令牌读取（`webgl.md` 第 8.3 节）。
- **腔体有自己的令牌集。**炉口内部、浇包、剖视所见容器内部、水柱或风道窗口更暗是有原因的：烟灰、耐火材料、深度、阴影。给它的分组一个类，把 `--anatomy-paper`、`--anatomy-face`、`--anatomy-top`、四档明暗与线色调重定义为更暗、更暖或更蓝的灰。保留全部色调使其仍有形体，用一个由实时代码写入的变量把它向光照色相混合，并在深色下把这些令牌设为 `inherit`。这样光晕有了底，而无须一个黑盒子。
- **留意嵌套主题。**深色底板可以放在浅色页面上。写成 `.iso:not([data-theme="dark"]) .x` 的规则也会穿透周围页面匹配。把深色规则排在浅色规则之后，或以底板自身的主题为键。
- **不透明度会把淡色褪成灰。**浅色下任何靠不透明度淡出的东西（回退光晕、点亮强调）都用饱和令牌，其淡染用正片叠底混合，使其下方的线条保持可见。

## 8. 圆形零件与管道

发动机、泵、阀、灯与仪器大多是车制零件与管道。`kit/lathe.mjs` 和 `kit/tube.mjs` 沿任意轴构建它们（`references/kit.md` 第 10、11 节）。`examples/raptor-engine/build.mjs` 以可运行形式收录了下面每个配方。

### 车制零件：以子午线思考
把零件写成它的半剖面：一串从一端到另一端的 `[s, r]` 列表，再用 `G.solidOf(profile, F, P)` 旋转成型。
- **台阶与轴肩**是半径在同一个 `s` 处跳变的地方：`[6, 12], [6, 9]`。它们产生读作机加工痕迹的折痕线。
- **曲线**是许多标记为平滑的点（`[s, r, 1]`），因此不横跨它们画折痕：钟形段、穹顶、并入法兰的圆角。工具包对任何含平滑顶点的剖面自动平滑着色（`smooth: "auto"`），着色跟随曲线而非逐面片成阶梯；只有要退出时才传 `smooth: false`。
- **收腰体绝不做凸包。**中部收窄的剖面（喉部、阀芯）有凹轮廓。当真实轮廓线落入其圆环凸包内侧超过半像素时 `lathe` 会察觉，然后改用轮廓线与可见端弧来填充与描边（`fill: "auto"`，或强制 `"surface"`）。按凸包绘制时，Raptor 喉部成了一个直锥，带一条苍白未着色的条带和一条距轮廓 8 px 就停住的缝。
- **曲面上的缝线与焊线**是 `G.arcOf(F, s, r, P, { slope })`，带上剖面在该环处的斜率，画成 `faint` 并作为实体的 `inner` 传入（`solidSvg(paths, { inner: lineSvg(arcOf(…), { tone: "faint" }) })`；Raptor 的 `S` 与 `Ln` 是对它们的一行封装），因此它们压在轮廓之下。它们恰好终止于轮廓缘、比它略短一点。若改在实体之后拼接，每条缝的圆头端帽会压上描边，Raptor 促动器筒身的深色主题轮廓在 4× 下看起来像虚线。
- **长体**（喷管、筒身）用 `G.bandsOf(profile, cuts, F, P, { radius, slope })` 切成环带，让每条带与缠绕它的管道做深度排序。各带共享同一个 `steps`、同一个法线场和同一个曲面，它们自身的轮廓被清除，`sidesOf` 为整个体画出一条连续轮廓（`kit.md` 第 10 节），于是色调曲线无台阶地穿过每个接缝、侧面不打折。没有解析的 `radius` 与 `slope` 时，它对整个剖面拟合一条曲线，绝不会每带一条。
- **环绕带的圆环**（燃烧室上的加强环、轴环）把带拆开：带、环、带。画成一条长带、环叠其上时，环的后半会盖住带（或带遮住环的前半）；拆开后每段自行排序。Raptor 燃烧室外套就是两环之间的三条带。
- **开口端**是一个 `ringBand` 唇口，配一个填充的空腔（`circleOf`）表现深色内部，以及来自 `arcOf(..., { inward: true, least: -1 })` 的内侧弧。螺栓圆点绕唇口排布。

### 圆形体上的零件
- **法兰：**其背面贴在路线端点上，因此路线恰好终止于安装面，圆盘从那里沿管道向后延伸（`centre = end − tangent · t/2`）。`disc(-t/2, t/2, r, frameAlong(centre, axis), P)`，在朝向观察者的面上加螺栓圆环 `dotsOf(F, faceS, 0.74r, 8, P, { all: true })`。面近乎侧对时跳过螺栓（`|dot(a, V)| < 0.12`）。
- **曲面壁上的凸台或端口：**沿外法线的一小段 `disc`，朝向你时加一个 `faint` 面环（`circleOf`）。感测线、点火器或火花塞落在这里。把它做得至少与落在其上的法兰一样宽；悬出凸台的法兰会悬浮在边缘。
- **鞍座垫。**平面法兰贴在曲面体上会在边缘留缝（矢高，`R − √(R² − a²)`）：18.4 泵体上一块 11.6 法兰在两侧翘起 4 单位。凡缝隙会超过约 0.15 之处，让法兰坐在垫块上：一个底面贴合宿主表面的短圆柱（`G.saddleOf(F, a, start, h, P)`，`start(angle)` 从宿主形状求得，即 Raptor 的 `padOn`/`boss(..., { host })`）。把它记录为被宿主 `cut` 并标记 `seated` 的圆盘，让审计看到真实形状。让垫块保持在宿主的一条带之内（跨在台阶下的悬出部分会被画在遮住它的带之前；Raptor 有个垫块降到边缘触及下方台阶后，每一帧都成了互锁）；并避开宿主的轮廓线：骑跨轮廓的垫块一半在前一半在后，任何画师顺序都画不出它。Raptor 的 LOX 管因此从 130° 挪到 150°。**鞍座属于宿主的组件。**它的底面按宿主曲面裁剪，所以若它随管道飞出，被裁的底面在分离态就露了馅：Raptor 的热气垫块按甲烷泵的涡轮与环裁剪，分离后成了一块带尖尾的锯齿碎片。把垫块交给宿主的部件（`boss("ftp", …, { host: FTP_TURBINE })`），让移动管道的法兰离开其平坦顶面；审计的 `seats` 会列出每个宿主随另一组件移动的贴合形状。
- **点火塞，单一端子。**一个塞子要么携带点火线（沿其轴从外端面引出），要么携带励磁电缆，绝不两者兼有。电缆落在它旁边自己的小凸台上。
- **管上的阀：**在 `frameAlong(point, tangent)` 上以 `smooth: true` 旋转成型一个鼓胀的 `lathe` 剖面，两端面有螺栓圆点、圆形颈部，还有一个带盖轮廓与两颗螺丝的执行器箱。它坐在一段直腿上（体长加两侧圆角切量），管道在其体下断开，执行器垂直于管道竖立：水平管上朝上、竖直管上朝侧（一个圆罐），绝不沿管道方向。
- **蜗壳：**把 `spiral(F, s, r0, r1, a0, a1)` 喂给 `tubePieces`，半径沿程增大。让其中线保持在机壳半径加管半径加 0.3，使它相切地包裹机壳；陷入机壳的蜗壳就是穿过实体的管道。
- **球关节与三通**是球体（`sphereOf`）：促动器上的杆端轴承、支管接入歧管处的铸造三通。
- **斜轴上的滚花、肋与散热片：**`ribsOf`。面上的叶片：带 `sweep` 的 `spokesOf`。

### 管道
- 把路线布成真实端口之间的几段直腿，再用约 2.6 × 管半径的弯头 `fillet`。管会弯；不会折成尖角。
- 每根管都终止于带法兰的端口，或带端点圆点（terminal dot）的块体。悬空停住的管就是一条悬空停住的线。
- 加上真实管线会有的部件：被夹持或焊接处的环带（`bands: [0.5]`）、必须挠曲处的波纹管（一串薄 `disc`，`bellows: [from, to, count]`）、控制流动处的阀。这些就是 Raptor `pipe()` 辅助函数的选项（`kit.md` 第 11 节）。
- 少用几种尺寸，都要大到足以区分：主导管（r 5–8）、供给线（r 2–4）、感测线（r 0.9–1.5）、电缆（r 0.5–0.65）。

### 选择路点
先布大线（导管、下降管、歧管），再供给线，再感测线，最后电缆，让每条更细的线绕过已布好的东西。对每条路线：
- **沿端口法线起步。**第一腿沿端口表面法线笔直引出，长到容得下法兰，然后转弯：`fillet` 至多占用较短腿的 0.48，所以短于约两倍弯曲半径的腿会得到急弯，而在正对观察者的端口处转弯会捏成尖点（"间距与交叉"第 5 步）。
- **跟随结构。**腿与所跟随的体平行（沿燃烧室、沿下降管向上），或以固定半径绕环（`arcPoints`），与表皮的偏移为该体自身的间距：表皮半径加约 1.5 × 线半径。所有者的特写显示感测线扇形铺过燃烧室表面、越过主导管去够它们的块体；新版里，从喷注歧管引出的长线沿左侧上行，燃料阀电缆沿下降管旁上行，线束（harness）从控制器以平行垂线落下、进入被线夹固定的走线通道（lane）。
- **待在主题的自己一侧。**服务于远端端口的线绕到背后、或在某环处绕到侧面，绝不斜穿被解释物体的正面。
- **优先横穿屏幕的腿。**直冲或背离观察者的腿投影很短，使其两端的每个转弯都成尖点或 V 形（"间距与交叉"第 4、5 步）。
- **给管件留空间。**阀、波纹管或线夹需要一段直腿，至少为体长加两侧的弯头让量（每侧 `r_bend · tan(turn / 2)`）。在弯头上直体段会切进管道；Raptor 的下降管因此改道，让阀坐在直段上，氧管则为阀加了一段竖直直管。
- **别落在杆上。**管道最后一腿不得在屏幕上沿某根杆、拉杆、立柱或导轨走，其末端管件也不得坐在它们的轮廓上：盲测台的软管最后一腿与一根拉杆平行、高 2 px，导致那根杆读作插进了软管接头。横跨各杆接近端口，或转动弯头让腿横躺屏幕。审计的 `crowding` 把每个细长实体（长度超过其半径或半宽 4×）当作线，因此会判这些失败。每个姿态也要检查：行程末端坐在运动板边缘上的箍套读作碰到了它。
- **有意地交叉。**若两线必须在屏幕上交叉，就交叉一次、在直段上、以清晰角度，且深度上离得足够远，让间距检查富余通过。弯头或端头附近的交叉读作接头（"间距与交叉"第 6 步）。
- **拆开，不要重叠。**凡某物包裹管道处（法兰、环带、波纹盘、线夹、阀体），管道在该处断开、每侧各有一段终止于其面（`tubePieces` 的 `gaps`，线夹用 `crossingsOf`）。作为一整块穿过时，管道既在轴环之后又在之前，任何键都无法排序。Raptor 燃烧室外套出于同样原因在其两个环处拆开。

### 接触与交汇
两零件相遇的每处，要么是平面贴平面、要么是相切接触、要么是边缘落在圆体上。没有任何东西沉入任何东西：沉入的零件既在宿主之前又在之后，任何画师顺序都画不出它。
- **齐平。**杆终止在其叉头端面上；凸台从所立表面起始；耳轴是从壳体到球的一枚短销。
- **边缘落在圆体上。**半径 `a` 的圆柱遇见半径 `R` 的球或管时，终止于其边缘落在表面的位置、距中心 `sqrt(R² − a²)`。这样它的端面藏在宿主内部，什么也不会透出来。Raptor 的促动器杆与球关节的相接、歧管管与下降管同三通的相接都是这样。
- **三通。**支管接入管道用一个比两者都略大的拟合球：主管在其边缘遇见球处断开，支管终止在球上。球的尺寸要让任一管的边缘都不戳进另一管：半径 `b` 的支管接入半径 `a` 的主管时，`R ≥ sqrt(a² + b²)`。
- **支撑柱（stand-off）。**必须沉入曲面体才能触到它的环（环绕钟形段的歧管）改用小径向垫块架空，间隙至少半个管半径。
- **阀与波纹管放在直段。**弯管上的直车制件在两端都会切进管子。把它们放在路线全程笔直的地方。
- **两个法兰，一个接缝。**导管螺栓连接到泵出口法兰处，导管自己的法兰与出口法兰面对面相接；同一位置的两个法兰会互锁。这样分离时每个零件都保有一个法兰。
- **支管带管件。**支管从三通离开主管（一个球、主管在其下断开、支管从其边缘遇见球处起始），或从主管上的鞍座垫离开，绝不从主管表皮的裸点离开。
- **撑杆以球关节收尾。**沿斜轴铺设的撑杆孔盘会沉入它遇见的任何东西。给每端一段沿宿主法线的短杆身、杆身上一个球，杆体介于两球之间（四处关节都是边缘落在球上）。
- **会动的关节用带平面的球。**在 3D 图里，边缘落在球上无法在所有角度下排序。给球一个平面（`T.ball({ flats: [{ n, d }] })`，记录为 `A.ball(c, r, { flats })`），让边缘落在平面上，或用同轴肘节盘。`references/3d.md` 第 5 节。
- **一切都有依托。**每个实体都通过接触连接到机架：托架承着箱体、螺柱承着线束线夹、齿轮箱板把电机接到其促动器。只触及它所夹线缆的线夹是悬浮的。

### 间距与交叉
管道中线与除自身连接点之外的任何东西保持约 1.5 个半径，所以一根 0.6 的电缆距导管表皮净空 0.3 通过，导管与邻居保持半个半径。两线必须在屏幕上交叉时，它们在深度上交叉、一者远在另一者之前，由分块键排序；管道穿过轴环、线夹或阀之处则断开（`kit.md` 第 11 节）。要证明，不要目测：
1. 构建时为每个元素和每根管记录形状，统一记入一个 `A.recorder(P, { order, spring })`（`kit.md` 第 12 节）：绘制的元素用 `R.put` 带 `shapes`，每个形状用 `R.solid`，每根管道和电缆用 `R.route`。让辅助函数代劳，别让任何东西漏网。工具包绘制的每样东西都有记录形状：地面棱柱用 `A.slab`、`A.extruded` 和 `A.cylinder`，车制件用 `A.solid`、`A.lathe` 和 `A.disc`（沿绘图所用的同一条曲线描迹），`prismOf` 用 `A.prism`，还有 `A.ball` 与管件。
2. 每次构建都用 `A.settle(R, P)` 敲定画师键：它测量图形在每个静止状态（组装态与分离态）以及真实爆炸动画每一帧（`explodeStates` 重放实时弹簧与错峰）中的重叠，并运行 `orderKeys`。
3. 构建以 `A.auditOrExit(R, P)` 收尾，并运行 `node build.mjs --audit` 直到每条失败行归零。互锁的一对是几何 bug（拆分、断开或相切接触能修复它）；不要用偏置掩盖它。
4. 线不在屏幕上折返。背离观察者走的水平腿读作向上走，所以一根先远离再下落的管读作尖点、读作悬空终止的管。先把腿在屏幕上改为侧向走（审计的 `folds` 会找出每一例：4 半径内屏幕转角超过 140° 而真实转角低于 110°）。
5. 轮廓不自我折返，弯头也不在屏幕上捏成一点。先指向观察者再转弯的腿（从外套凸台径向引出再爬向块体的感测线、从传感器尖端引出再回勾的盘管）其圆角以侧缘投影，两腿以无可见半径的 V 形相遇。`folds` 测量每个 90° 以上可见弯头的屏幕半径，低于管屏幕半径两倍即判失败。修复办法按优先次序：让转弯发生在管件内部（凸台上的球三通、线从那里引向下一个点：Raptor 的 `elbow`，sense0、sense2、sense5 与富燃料点火线都在用）；在面向观察者的平面内弯（Raptor 的盘管在传感器自身的径向平面内绕环，该平面正对相机；其局部辅助函数 `sideOn(d) = unit3(cross3(unit3(V − d·(V·d)), d))`，其中 `V = G.viewOf(P)`，给出从沿 `d` 的腿横穿屏幕的方向，因此在 `d` 与 `sideOn(d)` 所张平面内的弯正对观察者）；把端口挪到法线横穿屏幕的地方。弯折平面的法线与视线成 `f = |n·V|` 时，弯头投影的屏幕半径约为 `R·f²`；一旦低于管的屏幕半宽，单块的内缘会倒着走、轮廓在一小团结里自交（审计的 `selfOverlaps`）。`fillet(…, { P, tube })` 会抬高每个角的半径来避开这一点，但只能到两腿允许的程度，所以给端口旁的转弯至少 `R + 3r` 的直腿。正对观察者的端口（甲烷泵上的转速探头）让每种接近都成发卡弯：挪走它。
6. 交叉发生在直段上，清清楚楚。一条线的弯头或端头在屏幕上落在另一条的轮廓上（相触或有任意重叠）时，无论真实深度如何，眼睛读出的是一个接头或一条线穿进另一条：从感测线弯头后探出的盘管回勾、分离姿态下落在另一线环带上的法兰、屏幕上沿短导管走又压过其端法兰的电缆。管件也算：轮廓压在另一条线上的线束线夹读作那条线从线夹里长出来，Raptor 的线夹在氧-预燃室线的分离姿态下正是如此。审计的 `crowding` 列出组装态与分离态的每个可见案例；改道其中一条线，让相遇成为两条直段的清晰交叉或至少 1 像素的可见间隙（线夹为 2 像素）。只有在 8× 下看过之后才可豁免一对（`CROWD_OK`）。

第一版 Raptor 有 54 个间距问题（39 处穿透（pass-through））和 323 个深度顺序问题；本节的布线方法把两者都归了零。

### 曲面上的着色与纹理
- **平滑着色**（任何含平滑节点的剖面自动启用；解析曲线用 `smooth: { slope }` 或 `{ slope, radius }`；分带的体用 `bandsOf`；球用 `sphereOf`）用于每个曲面：钟形段、喉部、穹顶、锥、阀鼓胀、球。每行一个平面面片色调只对圆柱合适。只要区域数保持，每档色调就是覆盖整个体的一个多边形，因此不露行缝。
- **纹理终止于边缘或淡出，沿轴也一样。**每根肋的 `s0` 与 `s1` 恰好落在同一 `s` 处已绘制的台阶、折痕或缝弧上：传 `seams: true`，`ribsOf` 会连同肋一起返回两条缝弧，因此它们不会漂移分开（盲测电机把肋排在 26 到 88、缝在 24 与 90，结果每根肋两端都差 2 单位停住）。肋排没有缝时，让它延伸到终止该带的面上（`s0`、`s1` 等于带的端点）或让它淡出。
- **管上的纹理跟随其横截面。**编织、波纹、缠绕带与铠甲来自 `tubePieces(route, r, P, { rings: { pitch, twist, cross, fade } })`：环（带 `twist` 为螺旋线，带 `cross: true` 为双手向交织的编织）按 3D 弧长沿整条路线放置，每个都画成其横截面的可见前弧，向两侧轮廓淡出、终止于箍套面与断开面。绝不要用沿分块中线的 `stroke-dasharray`：它沿软管方向以笔直硬边告终、不包裹圆截面、在弯头内侧堆积，且在每个分块接缝处重新开始。
- **纹理终止于边缘或淡出。**只保留面向你一侧的肋与螺栓圆环会停在截断点落下之处、即表面正中：Raptor 燃烧室环上的螺栓圆环在所有者的特写里正是如此。用 `ribsOf(..., { fade })` 配 `fadedSvg`，用 `dotsOf(..., { fade })`，让它们朝转弯处淡出（Raptor 对螺栓圆点用 `fade: [0.04, 0.42]`、对肋用 `[0.1, 0.55]`）。缝弧与带线本就终止在轮廓上。必须在面中央停住的单条纹理线（中途到头的凹槽、距角尚差的焊道）用 `fadeLineSvg(points, { fade: [start, end] })` 绘制，它沿线以渐变在几 px 内淡出；绝不让它终止在裸切线上。截断依据特征的朝向选择，而不是它所在的环：喷淋环顶部的喷孔朝上、整圈都可见，所以取 `all: true`。按环的外法线剔除（`least: -0.2`）时，Raptor 的那排孔在刚过环两侧处满强度截停，而环却光秃秃地继续绕到背面。绝不要用径向 `least` 截断朝上特征的一排；若它确实有部分被遮住，就朝转弯处 `fade`。
- **平滑色调渐变收束。**色调带沿曲剖面出现或消失之处，它以零宽度诞生并逐渐变宽（`smooth` 按屏幕误差细化行，直到每条边界在 0.35 px 以内、每次带数变化都发生在一条细缝里）。终止于横切表面的直线切口上的带、或一块苍白的裸填充楔形，是评审最先发现的 bug。
- **形状与着色描述同一条曲线。**剖面的平滑段用单调三次 Hermite 曲线（Fritsch–Carlson）插值，工具包对法线、色调面、轮廓与凸包都用同一条曲线。自然样条在峰值附近会过冲：在 Raptor 的阀上，它给一个只升降一次的体塞进了三次斜率变号，色调带像木纹一样在鼓包上锯齿穿行，而轮廓仍是一条在每个剖面点都带小鼓包的折线。单调曲线只能在剖面转向的地方转向。
- **单调 Hermite 只有 C1。**它的 `dr/ds` 是分段二次曲线：手工敲入的节点会让它在每个节点处平台化、在节点间过冲，跟随斜率的色调带便先停顿再猛跳，形成扇贝状的色阶阶梯。Raptor 喉部在只朝一个方向弯的剖面上有五处斜率极值；其甲板锥的晃动较轻。任何大于管件的曲面体都需要解析剖面 `r(s)` 及其导数、以 `smooth: { slope }` 传入、在 20–30 个节点采样：喉部是 `√(24.2² + (c·(s − 146))²)`，锥是 `48·(1 − x)^0.8` 并在尖端以竖直切线闭合到 `r = 0`，这样轮廓绕过尖端成圆、而不是在平坦尖端圆盘上方耸峰。审计的 `wobble` 会让任何未带 `slope` 平滑、且 `dr/ds` 在两端之间转向的剖面失败。
- **轮廓是椭圆，不是面片多边形。**面片数只用于色调填充（屏幕上每面片约 3 px，`stepsFor(r, 32, 160, scale)`）；每条轮廓线、边缘和折痕都以约 1.5 px 从解析圆采样，折痕与斜切面恰好终止在面转向之处。20 边的法兰轮廓挨着 96 采样的圆环，在 4× 下读作一个缺口。
- **管上的条带。**高光与阴影带连续贯穿分块接缝、一直到最末端：在每个封头端，它们沿端椭圆的外半周走；在转向你的端面处，它们停在所绘内缘上。在接缝处，条带比体再多悬出 0.5（体重叠 0.5、条带重叠 1），且每帧都从整条路线计算，于是后一块的条带盖住自身体的抗锯齿切口、终止在完全相同的条带上。体与条带在同一条线上截断时，蜗壳的阴影带在每个接缝处都横过一条发丝线，浅色主题下是亮的、深色主题下是暗的。在每个弯头、三通、波纹管和法兰处，以及在强弯曲的锥形管上，用 4× 检查它们。你自己在分块上画的任何东西（纹理、流痕）遵循同一规则：从整条路线计算、按距路线起点的 3D 弧长定相位、并延伸覆盖分块的条带悬出量（每个接缝外 1 单位），否则接缝会显出半截虚线、重复标记或缺口。`rings` 选项替你做好了这件事。

### 线束布线
电缆是毁掉一幅图最容易的方式：横穿主题正面的电缆读作涂鸦。像真实线束那样布线：
- **走线通道。**电缆在环绕机体的环上以平行走线通道布设（固定 `s` 处的 `arcPoints`，r 0.62 的电缆每条通道向外偏 1.4 单位、沿程偏 0.2）。它们只在分支去插头时离开通道。
- **按序进入。**电缆从连接器以平行垂线落下，在其垂线与通道相遇处（`acos(x / laneR)`）汇入环，于是最内圈通道由最靠前的连接器供给、没有任何垂线交叉。
- **按序离开。**最外圈通道先离开环；外圈通道还在旁边走时，向外转的内圈电缆不得不交叉。
- **跟随结构。**必须爬升的电缆沿管道旁上行（Raptor 的阀电缆沿下降管上行），而不是横穿发动机前的空旷区。
- **短分支。**从通道直接走向端口。不要斜穿主题正面。
- **线夹**（`disc(-0.9, 0.9, r, frameAlong(point, tangent))`，色调 `mid`）以规则的角度间隔把通道固定在机体上。每根电缆穿过线夹处断开（`crossingsOf`），否则线夹与电缆互锁。
- **端头有落点。**每根电缆起于控制器或接线盒上的连接器，终于插头、传感器尖端、阀盖或穿舱连接器，绝不终于线夹或线束旁的空中。留在自身组件内的端头得到一个端点圆点；落在另一组件上的端头得到一个随电缆移动的连接器外壳（`cable(..., { shells: [false, true] })`）。
- **数一数你画了什么。**把每条路线推进一个列表（`CABLES`），读数从其长度构建。第一版 Raptor 的读数声称 8 根电缆，实际画了 11 根。

## 9. 爆炸图

当零件本身就是解释（什么供给什么、按什么顺序）时，爆炸图（exploded view）才配得上它的位置：
- 选择真实物体实际拆分成的组件（Raptor 有 11 个），而不是单个实体。
- 让每个组件沿其真实拆卸方向移动，远到其轮廓让开邻居：堆叠级沿轴向下，侧置单元沿径向向外。
- **每个零件都有归属。**桥接两个组件的零件（促动器、电缆）随保持连接的那个走，分离时仍终止在属于自己的东西上：一个法兰、快拆接头处的连接螺母、电缆上的连接器外壳。撑杆端是宿主上的球头螺柱、杆体随其组件离开，鞍座垫留在宿主上。标记分离时脱离安装座的每个端头（`free: [true, false]`）；审计的 `looseEnds`（悬空端（loose end）检查）会判失败其余每一个在分离态未触及任何其他归属之物的端头，并列出自由的那些，让每个都是有意的选择。
- **高亮与运动彼此独立。**螺栓固定在燃烧室上的传感器随管路高亮，但乘骑燃烧室的弹簧（`ride`，输出为 `data-ride`）。若用另一组件的向量、在自己的弹簧上移动，它会沿安装座滑移并在中途沉入其中。
- 选择爆炸向量与错峰，让任何东西在任何一帧都不穿过任何东西：`references/motion.md`（"安排错峰，让什么都不必穿透"）有这些规则；审计会重放真实弹簧的每一帧——展开、合拢、中途反向——并在任何穿透上报失败。
- 在图例中把组件列为带编号的按钮（`01 Gimbal and thrust puck`…）供选择，与悬停的效果相同。
- 弹簧、错峰与逐帧深度重排见 `references/motion.md`。

## 10. 屏幕与面上的元素

屏幕、表盘面或显示器绘制在其所在面的平面内（`examples/desk-computer/`）：
- **面平面。**`sideMatrix([0, y], 0, P, "left")` 把分组的局部 `(x, −z)` 坐标映射到 `y` 处的竖直面上。屏幕上的一切（辉光、扫描线、标记、`<text>` 与光标）都在该 `<g transform>` 内以这些平面坐标绘制。
- **凹槽。**用同一平面内的 `clipPath` 把屏幕裁剪到其圆角轮廓，并把凹槽的内侧画成面与后移 `depth` 的面之间的四边形。侧面按朝向着色（顶面用 `iso-top`，侧面按明暗）。轮廓在面上画 `lo`、在背面画 `faint`。
- **面上的运动**是面坐标中的变换。CRT 关机把画面绕屏幕中心缩成一条线、再缩成一个点，带一条束线和一个渐隐的亮点。
- **机器显示的文字**（打出的行、计数器的数字）是物件的一部分而不是标签，因此单标签规则不适用。保持屏幕自身的字体与字号，并做好适配：大写高度约为窗口高度的 0.55，你将显示的最宽字符串（`8.88`，最长的单位）必须以约十分之一高度的边距容入其宽度。像任何屏幕一样把它裁剪到窗口内。一个盲测流量计在 12.8 × 8 的窗口里放了 5.6 px 的数字，于是首位数字越过了窗口左边框、数字顶端顶进了单位标签。
- **透过开口看到的内容**（视油镜、表窗、凹槽）位于面之后，因此在面与背板之间画开口的内壁、按朝向着色，并把内容同时裁剪到面平面内的开口与其自身范围内。开口内一条裸面窄条读作画在表面上的一个洞。开口后方的着色器见 `webgl.md` 第 5 节。

## 11. 着色器

有些题材无法用线条绘制：火、尾焰、水、焦散、真实的灯光、蒸汽。它们放进绘图*内部*的一个 WebGL 层，处于世界空间与同一相机中，位于后置 SVG 与前置 SVG 之间。`references/webgl.md` 包含层叠结构、相机契约、工艺规则（绝不突现、绝无硬截断、色调映射与抖动、按主题混合）以及如何验证它们。本页的一切仍然适用于特效周围的 SVG。其第 8 节讲述作为发布主题的浅色：从纸面应显示的颜色解出墨色、随光增强的墨色、每团光晕的深色物理底、热金属、玻璃、火花、火焰、蒸汽、等离子体与切伦科夫光的配方，以及与着色器匹配的无 WebGL 回退。
