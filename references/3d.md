# 3D：图中转动的部件

可选的 3D 模式（"转动组"（turning groups））让图中的一些部件作为刚体运动：旋转的刻度盘或转台、会弯曲的手指、断裂后翻滚的碎片。这些部件每帧都由套件自身的规则重新投影、重新着色，并按由分离平面（separating plane）解出的顺序绘制。其余一切都保持普通的静态套件图。未选择加入的图完全不受影响。

**状态：beta。** 引擎已在 `examples/turning-dial` 与一个测试图（仅凭本文档构建的桌面风扇）上得到验证，尚未在生产图上验证。一次只转动一个主体，让杂物保持静态，并在添加部件之前对照第 15 节衡量你的图。

## 1. 图何时值得用 3D

只有当运动本身就是解释时才用 3D：刻度盘转动中读数、转台全方位展示物体、轮组、抓握或断裂的手。绝不作为装饰。只需要某个部件滑动或指针摆动的图保持 2D：`translateAlong` 和重绘指针更便宜且精确。

## 2. 模型

- **组。** 组是带有姿态（pose）的刚体坐标系。类型：`turn`（绕过 `pivot` 的竖直轴旋转，任意角度）、`slide`（沿一个方向平移，`0…travel`）、`hinge`（铰链：绕过某点的任意轴旋转，在 `range` 内，单位为度）与 `free`（自由组：任意旋转加平移，由图每帧设置）。组可嵌套：姿态相对于父组。
- **静止态（rest）。** 每个构造器接受**静止时的世界坐标**（所有组值为 0，所有自由组为 `null`）。引擎会减去每组的原点，因此记录器（`A.recorder`）、套件与引擎共享同一个世界。
- **活动层（live layer）。** 活动层是舞台中的一个 `<svg class="iso-svg iso-live" data-live="name">`。活动层与静态层按 `T.stack([...])` 的顺序堆叠：例如 `back svg → [dial live] → back canvas → [hand live] → front canvas → front svg`。
- **恒等式。** 绕竖直轴把组旋转 θ，恰好等价于套件在方位角 `a − θ` 处的绘制，因为套件的光线是锁定相机的。因此转动组的每一帧都是套件在 P′(θ) 处自己的画面加平移；P′(θ) 处的套件构建器是保真度基准，且每个套件屏幕空间审计都在 P′(θ) 处原样运行。铰链和自由组则改为矩阵合成（正确，稍慢）。

## 3. 最小页面

`examples/turning-dial/` 是参考场景：带滚花、刻度与数字的刻度盘、第二个转动组（视窗下的分度轮）、一个铰链（骑在滚花上的棘爪）、一只约 80 个部件带材质的手、一根抬起的三铰链手指、一个作为自由组脱落的六角块，以及 WebGL LED、光池与火花。`examples/turning-dial/stress.mjs` 是性能场景（杂乱车间里转台上的一只密集的手）；它不是审计干净的场景，模式请取自 `build.mjs`。

`build.mjs`，压缩到骨架：
```js
import * as k from "../../kit/iso-kit.mjs";
import * as A from "../../kit/audit.mjs";
import { turning } from "../../kit/turn-build.mjs";
import * as TA from "../../kit/turn-audit.mjs";
import { turnScript, glScript } from "../../scripts/inline-kit.mjs";

export const P = k.fitProjection(points, W, H, { pad: 22, azimuth: 40, elevation: 31 });
export const R = A.recorder(P);
export const T = turning(P, { recorder: R });
const dial = T.group("dial", { turn: { pivot: [0, 0] } });
const lift = T.group("f2.mcp", { parent: dial, hinge: { point: C1, axis: w, range: [-22, 0] } });
const hand = T.layer("hand");
T.stack(["back", "hand", "front"]);
export const follow = (values) => ({ ...values, "f2.mcp": -22 * (values.lift ?? 0) });
export const poses = () => Array.from({ length: 720 }, (_, i) => follow({ dial: i * 0.5, lift: (i % 90) / 90 }));

T.round({ name: "dial.body", group: dial, layer: hand, F: VERT(0, 0), s0: 10, s1: 14.4, r: 50, material: "steel", details: { ribs: { s0: 10.9, s1: 13.7, count: 150, seams: true, tone: "lo" } } });
T.prism({ name: "hand.palm", group: dial, layer: hand, plan: PALM, z: 19.4, h: 8, bevel: 0.9, material: "gold" });
T.tube({ name: "cable.red", group: dial, layer: hand, route, r: 0.7, hue: "red", material: "rubber", gaps });
// … static kit art: R.put({ name, layer: "back", svg, shapes }) as usual …

const out = T.build({ statics: R.items, poses, verify: argv.includes("--verify") });
A.settle(R, P);
if (argv.includes("--audit")) {
  A.auditOrExit(R, P);
  TA.orbitOrExit(T, R, P, { sweep: { at: (x) => follow({ dial: x }), from: 0, to: 360, frame: 0.3 }, clips: [{ name: "tap", at: (t) => follow({ dial: 40 + 12 * t, lift: tapAt(t) }), from: 0, to: 4, frame: 1 / 60 }] });
}
const stage = `<div class="iso-stage iso-turn" tabindex="0" role="slider" …>${backSvg}${out.layerSvg("hand", { width: W, height: H })}${frontSvg}</div>`;
const page = k.pageHtml({ title, theme, body: k.plateHtml({ …, body: `<style>${out.css}</style>${stage}` }), script: turnScript() + LIVE });
```
`live.js`：
```js
const controller = TURN.mount(stage, DATA.turn, { follow, onHold: () => (touring = false), onFrame: () => paint() });
function tick(now) {
  …
  controller.set({ dial: angle, lift });
  frame = visible && moving ? requestAnimationFrame(tick) : 0;
}
```
图拥有主循环（`motion.md`）；控制器从不运行自己的 `requestAnimationFrame`。`out.css` 即 `TURN_CSS`（表面色带规则、材质、色相管线与 `.iso-turn` 堆叠）：只需引入一次。

**在 React 或 Next.js 中**（`references/react.md`）：把 `turn.mjs`、`turn-build.mjs` 与 `turn-audit.mjs` 复制到套件旁并重写导入（`./iso-kit.mjs` → `./kit`，依此类推），`TURN_CSS` 作为只引入一次的 `turn.css`。几何模块（服务端）运行 `turning(…)` 与 `T.build(…)`，返回舞台标记（每个活动层一个 `out.layerSvg(name, { width, height })`，按堆叠顺序放在静态 SVG 与画布之间）以及图数据中的 `out.data`。客户端挂载调用 `TURN.mount(stageElement, data.turn, { follow, onHold, onFrame })`，并从自己的循环驱动 `controller.set(...)`；在 effect 的清理函数中返回 `controller.destroy`。verify 构建可把 `out.verify` 放进数据，让挂载把它赋给 `window.__isoVerify`，供 `turn-check --order` 使用。

## 4. 创作 API

### 场景
| 调用 | 作用 |
|---|---|
| `turning(P, { recorder, scale = 1 })` | 构建器 `T`。传入套件记录器，使每个活动形状也被记录进套件审计。 |
| `T.group(name, { parent?, turn: { pivot: [x, y] } })` | 绕过 `pivot` 的竖直轴旋转，值以度计。 |
| `T.group(name, { parent?, slide: { direction, travel } })` | 平移，值 `0…travel` 世界单位。 |
| `T.group(name, { parent?, hinge: { point, axis, range: [lo, hi] } })` | 绕过 `point` 的 `axis` 旋转，值以度计且在 `range` 内。 |
| `T.group(name, { parent?, free: { origin } })` | 自由刚体（第 7 节）。值为 `{ R: [9] \| q: [x, y, z, w] \| axis, angle, t: [3], world? }`，静止时为 `null`。 |
| `T.layer(name)`、`T.stack([…])` | 活动层，以及从后到前的活动与静态层名完整堆叠。 |
| `T.build({ statics, poses, verify = false, strict = true })` | 求解每一对部件、证明每个静态项的层归属、打包页面数据。`poses` 是图可达状态的集合（一个列表或返回单个状态的函数）：对每个运动片段采样。对任何没有分离平面的部件对、任何无法证明归属的静态项、任何非凸（convex）部件，抛出可读的错误。`strict: false` 保留互锁的对（这样植入的故障能到达审计）。 |

`T.build` 返回 `out = { svg, data, css, report, layerSvg(name, { width, height }), verify }`。`out.data` 交给页面（`DATA.turn`）。`out.report` 含 `parts`、`layers`（每层的 `planar`、`framed`、`dynamic`、`skip` 计数）、`tight`、`margins`、`proofs`、`seconds`。

### 构造器
每个构造器的通用选项：`{ name, group, layer, tone = "hi", crease = "faint", lit = false, material, owner, details = {} }`。

| 构造器 | 部件 |
|---|---|
| `T.prism({ plan, z, h, steps, bevel })` | 直立的套件板（套件 `extrude` 规则）。 |
| `T.prism({ F, polygon, s0, s1, round = 0, steps = 4, bevel = 0 })` | 坐标系 `F = { o, a, u, v }` 中的凸多边形，沿 `F.a` 从 `s0` 挤出到 `s1`，任意轴向（`prismOf` 规则）。 |
| `T.round({ F, s0, s1, r \| [r0, r1], ends = ["flat", "flat"], fixed })` | 圆柱或圆台；每端为 `"flat"`、`"dome"`（半径须与侧面相等：即胶囊体）或 `"open"`。一端 dome 一端 flat 是半胶囊，任意长度都成立，甚至短于半径（电机罐上的鼻锥）。直立组中的竖直 round 会自动成为 `fixed` 画面（`fixed: false` 可关闭）。 |
| `T.lathe({ F, profile, slope, radius })` | 一般凸平滑体（r(s) 为凹函数）。代价高；优先用 round。 |
| `T.ball({ c, r, flats: [{ n, d }] })` | 球体；每个平面（flat）保持 n·(p − c) ≤ d，并把其边缘画成盖帽，所以 `n` 是平面的外法线。无 flats 时它是 `fixed` 画面，且不接受 `details`。它是绘制代价最高的种类（第 15 节）。 |
| `T.tube({ route, r, chunk = 6, turn = 20, gaps, breaks, caps, rings, hue, material, bundle, owner, touch })` | 套件 `tubePieces` 语义，分块；`hue` 为 `"red" \| "green" \| "blue"`；记录 `R.route`。路线从安装面到安装面。每端的端口、密封接头或夹头是单独部件，`owner` 设为该管的名字，其沿路线的跨度记入 `gaps`。从端口外表面出发的路线会过不了套件审计的 `terminals`（见下）。 |
| `T.fixed({ svg, anchor, shapes, hull, F })` | 在组运动下画面永不改变的任何套件标记，用 `translate` 移动。 |
| `T.plane({ part, o, u, v, svg, fade = [0.04, 0.3], normal })` | 部件某个平面上的线条或文本标记（刻度、数字、铭牌），由单个矩阵放置，随朝向淡出。 |
| `T.billboard({ part, at, normal, svg, fade })` | 投影点处的屏幕对齐标记（着色器辉光的 SVG 回退），随朝向淡出。`svg` 以 viewBox 像素为单位、以投影点为中心，而不是世界单位：世界尺寸需乘 `G.scaleOf(P)`（`<circle r="${(1.1 * G.scaleOf(P)).toFixed(2)}"/>` 恰好填满半径 1.1 的透镜）。 |
| `T.split(part, { n, d })` | 被该平面切成的两个部件（prism：沿轴或横轴穿过它的任意平面；round：横切）。切口边不描边。用它打破真正的环。 |

### 细节（在部件坐标系内：`s` 沿轴，`x` 与 `y` 在 `u` 与 `v` 上）
每个构造器有自己的坐标系，只接受自己的细节种类。其他任何内容都会被忽略，且无警告。

| 构造器 | 坐标系 `[s, x, y]` | 接受 |
|---|---|---|
| `T.round`、`T.lathe` | `F`：`s` 沿 `F.a`，`x` 沿 `F.u`，`y` 沿 `F.v` | `seams`、`ribs`、`bolts`、`dots`、`rings`、`rules` |
| `T.prism({ F, polygon })` | `F` | `dots`、`seams`、`bevel` |
| `T.prism({ plan, z, h })` | 世界坐标：`s` 是 z，`x`、`y` 是世界 x 和 y | `dots`、`seams`（z 值）、`bevel` |
| `T.ball` 带 flats | 原点 `c`，`a` = 第一个 flat 的 `n`，`u`、`v` 来自 `G.frameAlong(c, n)`。flat 位于 `s = d`，远极位于 `s = −r` | `bolts`、`dots`、`rings`、`rules` |
| `T.ball` 无 flats | 无：是 fixed 画面 | 不接受 |
| `T.fixed({ F })` | `F`（无 `F`：无细节） | `bolts`、`dots`、`rings`、`rules` |

带 dome 的旋转体 `T.ball({ c, r: 4.5, flats: [{ n: [-1, 0, 0], d: 0 }] })`（flat 朝 −x，dome 朝 +x）上的中心点应放在 `at: [-4.5, 0, 0], normal: [1, 0, 0]`：`s = −r` 是极点。`[4.5, 0, 0]` 会落在 flat 后方 4.5 处，即旋转体安装载体的内部。棱柱面上的圆环或线用 `T.plane`。
```js
details: {
  seams: [s…],                                              // rings on rounds, ring seams on prisms
  ribs: { s0, s1, count, phase, twist, fade: [0.1, 0.55], seams: true, tone },   // knurl rows on rounds
  bolts: [{ s, r, count, phase, size: 0.5, tone: "mid", fade: [0.04, 0.42] }],   // bolt circles
  dots: [{ at: [s, x, y], normal, size, tone }],
  rings: [{ at: [s, x, y], normal, r, tone }],              // become planes
  rules: [{ points: [[s, x, y]…], tone, free }],            // become planes
  bevel: 0.4…1.6,                                           // prism cap bevel (faded slots)
}
```
每种细节都随朝向淡出：dots 与 bolts 按 `smoothstep(0.04, 0.42, n·V)`，ribs 逐根，bevel 线逐条边，planes 按所在组的不透明度。没有任何纹理以满强度常驻。

### 运行时（`kit/turn.mjs`，经 `turnScript()` 内联）
| 调用 | 作用 |
|---|---|
| `TURN.mount(stage, data, { onHold, onFrame, follow })` | 绑定 `stage` 中每个活动层，渲染静止姿态，安装 `window.__isoTurn`。`follow(values)` 在每次 `set` 时把图的值映射为组值（一个输入驱动相互耦合的组）。`onFrame(controller)` 在每次渲染后运行（在此绘制着色器）。`onHold()` 在工具调用钩子时运行。 |
| `controller.set(values \| θ, { detail })` | 设置组值（数字设置第一个转动组），同步渲染，返回统计。`detail`（0…1）缩放淡出的线、ribs 与 dots（第 15 节）。 |
| `controller.angleAt(clientX, clientY, z, group)` | 在高度 `z` 的平面上、绕组枢轴（pivot）的指针展开角（拖动刻度盘用）。 |
| `controller.pose(name)` | 组的世界姿态 `{ R, t }`。 |
| `controller.detach(name)` | 让自由组的当前姿态在世界系中延续（无跳变）的 `{ world: true, R, t }` 值。 |
| `controller.anchor(group, restPoint, restDir?)` | 组的某个静止世界点（及方向）现在的位置：`{ world, screen, direction }`。火花源、火焰根部、LED 位置。 |
| `controller.cover(names, options)`、`order(layer)`、`orderIndex(layer)`、`events()`、`stats()`、`frames()`、`cams()`、`scene()`、`values`、`destroy()` | 遮罩（第 12 节）、绘制顺序、顺序变化事件、`{ ms, writes, moved, forced, refined, unseparated, emitted }`。 |
| `TURN.cover(controller, names \| [names, names…], { polygons = 6, edges = 10, pad = 0.3, layers })` | 供 `coverOf` 使用的 `{ uCoverEdge, uCoverCount, dropped, parts }`。 |
| `TURN.poseUniforms(controller, group, prefix = "uGroup")` | `{ prefixX, prefixY, prefixZ, prefixT }`，使 `toGroup(p)` 给出组的**静止世界**坐标。 |
| `TURN.materials`、`TURN.materialCss()` | 材质名列表；单独的材质 CSS（已包含在 `TURN_CSS` 中）。 |
| `TURN.exact(on)` | 路径坐标以未取整形式（6 位小数）写出，而不是取整到 0.01 px。环视审计为 continuity 检查行打开它；页面从不需要。 |
| `TURN.rotation(axis, degrees)`、`TURN.quat(q)`、`TURN.compose(A, B)` | 以数组表示的 3×3 旋转，供自由姿态使用。 |
| `TURN.floorOf(scene, group, R)` | 组的部件在旋转 `R` 下（相对其原点）的最低 z：用于把部件齐平放落地。 |
| `window.__isoTurn` | `{ controller, set, get, order, events, stats, layers }`；每次调用都会挂起图（`onHold`）。`set` 接受数字或值对象。 |

## 5. 部件种类与使其成立的规则

这些规则有约束力；不满足则构建与审计都会失败。
- **只允许凸部件。** 阶梯刻度盘是分层的圆台；开槽的轮是轮毂盘加轮缘扇段；U 形支架是三根棱柱；手的外壳是若干板件。`T.prism` 检查其多边形，`T.lathe` 检查其轮廓。
- **接触只能是齐平、相切或"边缘落在平面上"（rim-on-flat）。** 球面上的边缘不可分离：给球加一个 flat（`T.ball({ flats })`），把边缘落在它上面。活动层中不允许出现沉入宿主的垫块（`separation` 失败，报 `interlock A × B −0.6`）。
- **关节。** 两个连杆保持至少 0.2 的间距，关节由子组上的铰节盘（knuckle disc）桥接：与铰链轴同轴，并接触父组连杆——齐平或相切。与自身铰链同轴的盘（或任何在其自身平面内转动的平直面）在铰链运动下保持不变，因此永不碰撞，而它正是套件审计所需的那个接触。若子组内没有任何部件接触父组，`rigid` 会把子组的每个部件报为 `support loose`。在关节处相接的连杆共享同一半径；dome 中心与关节保持等距，使间隙在任何角度下都成立（半径为 r、中心距关节 c 的两个 dome，只要 cos(β/2) ≥ r/c 就不会相碰）。轭架上的耳轴（trunnion）：
  ```js
  T.round({ name: "yaw.arm+", group: yaw, layer, F: VERT(0, 11.7), s0: 40, s1: 61, r: 1 });
  T.round({ name: "head.can", group: tilt, layer, F: frameOf([0, 0, 56], [1, 0, 0], [0, 0, 1]), s0: -12, s1: 8, r: 9 });
  T.round({ name: "head.trunnion+", group: tilt, layer, F: frameOf([0, 9, 56], [0, 1, 0], [0, 0, 1]), s0: 0, s1: 1.7, r: 4.5 });
  ```
  `tilt` 绕过 `[0, 0, 56]` 的 y 轴铰接。can 伸到 y = 9，arm 从 y = 10.7 开始，所以两连杆相距 1.7。trunnion 从 9 延伸到 10.7：它坐在 can 上，端面与 arm 相切。若让它止于 10.5、与 arm 留 0.2 间隙，整个头部会通不过 `rigid`。
- **活动线不得跨越两个运动组。** 跨越弯曲关节的缆或软管是两条路线，各自终止于关节一侧的夹头或端口；或在铰链轴处穿过一个旋转接头（banjo）。必须从静止地面到达转动部件的缆，沿轴向上穿过轮毂处的滑环（slip ring）（第 11 节）。
- **管子只在近水平处弯折，或在管件内弯折。** 在与水平面成 θ 倾角、朝向观察者的平面内，半径 R 的弯折在屏幕上呈椭圆，其最紧半径为 R·sin²(e − θ)（世界单位；换算 px 乘 `G.scaleOf(P)`）。`folds` 判定屏幕上在小于 2r 的半径内转过 90° 以上的弯折为失败，`self` 判定小于 r 的为失败。所以弯折需要 **R ≥ 2r / sin²(e − θmax)**，其中 θmax 是平面自身倾角加上它所骑乘的每根铰链的俯仰范围（转动组会把倾角扫过全部方位角，最坏情形总会转回来）。e = 30° 时：

  | θmax | 0° | 5° | 8° | 10° | 12° | 15° | 20° |
  |---|---|---|---|---|---|---|---|
  | R ≥ | 8r | 11r | 14r | 17r | 21r | 30r | 66r |

  8r 是水平面上界限本身，并非余量：请取 10r。超过约 15° 就没有实用的半径能成立，所以要在管件内转向（夹块、banjo、弯头球、接线盒），或让线走直。弯折用 `G.fillet(points, R)` 绘制，绝不用依赖视点的圆角。审计的 `folds` 与 `self` 在每个角度与姿态下运行。
- **管子绝不指向视线方向。** e = 30° 时，管切线的仰角在每个姿态下都要避开 15°–45° 与 −45°–−15°（`endon`）：在铰链链上，还要检查连杆的俯仰范围（在弯曲 30° 的连杆上的缆线会失败）。
- **lathe 是唯一保留小残余台阶的种类**（在色带改变拓扑处 ≤ 2.5 tone·px²）。活动部件优先用 round、dome 与带 flats 的 ball。

## 6. 材质

部件的材质是构造器上的一个选项（`material: "gold"`）。色调仍完全像套件那样来自朝向；材质重映射色阶（四种色度、顶部、纸面、描边与线条色、dots 与管身、高光与阴影），且各配一套浅色版与深色版。

| 材质 | 外观 |
|---|---|
| `gold` | 香槟金阳极氧化铝：暖调浅色顶部，青铜色阴影，深青铜描边。 |
| `chrome` | 明亮抛光钢：浅色远带，紧邻亮带与白色高光的深色反射带（n·L 0.2–0.42）。刻意做成非单调：色带随朝向移动，从不跳变。 |
| `steel` | 缎面钢，单调而冷。 |
| `gunmetal` | 带浅色点的深蓝灰金属。 |
| `rubber` | 黑色橡胶与缆线护套，带柔和光泽。配 `hue` 时，管变成彩色护套（色相混入橡胶色阶）。 |
| `brass`、`copper` | 暖色金属，用于管件、端口、阀门。 |

静态部件使用与普通 class 相同的家族：把套件标记包进 `<g data-mat="brass">…</g>`（示例中的分度楔块）。规则位于 `TURN_CSS`；纯静态图的页面可引入 `TURN.materialCss()`。浅色页面中的深色板面会取深色集（`.iso[data-theme="dark"] [data-mat]` 排在最后）。

浅色页面上，材质图远比套件灰阶有力：把地面（工作台、底座、板面）留在套件色调里，把材质用在主体上，让它读作被照亮、已完工的物件。

## 7. 自由组：会脱落的部件

`T.group("pod", { parent: dial, free: { origin } })` 创建一个刚体，其姿态由图每帧设定。静止（`null`）时，它精确停在构建的位置，处于附着状态：由父组携带。要让它脱落，开始设置相对父组的姿态即可：不会有单帧跳变，因为第一个值就是恒等。
- **落到转台上**：保持父组为转台组，部件落地后随之转动。把飞行算成时间的纯函数（示例中的 `breakAt(t)`：绕质心的翻滚、抛物线弧、用 `TURN.floorOf` 求得的齐平落地、衰减的滑动与偏航）。纯函数可被构建与审计采样，也可倒放。
- **掉落到工作台上**：用 `controller.detach(name)` 切到世界空间，它返回延续当前姿态的 `{ world: true, R, t }`，然后从那里继续积分。
- **顺序**：自由组的部件在运行时与其所在层的每个部件配对（先按屏幕包围盒，再按按相对姿态缓存的 GJK 平面）；组内配对是平面型的。自由部件之间原则上可能出现环；审计会采样各片段并报告。
- **证明**：把各片段给到构建的 `poses()`（断裂在若干转角下的每一帧），并把同样片段给到审计（`clips`）。审计在每个片段帧中摆出每个形状的姿态，并检查与活动、静态部件的间隙（`posed`）、顺序、环与连续性。

## 8. 铰链链：手与手指

每个连杆是一个铰链组，其父组是上一个连杆（`T.group("f0.j1", { parent: f0j0, hinge: { point: J1, axis: w, range } })`）。腕是承载手掌的铰链；拇指根是承载拇指链的铰链（竖直轴）。通过 `follow` 用一个图值驱动整条链（`lift` → 三个角度）。
- 不同连杆上的部件对尽可能在构建期求解：若一对部件在构建的 `poses()` 全程扫掠后，其共同祖先坐标系中存在余量 ≥ 0.1 的平面，该对就成为 **framed** 平面（运行时无需 GJK）。只有近关节对保持动态（GJK，热启动，在两组保持相对姿态期间缓存）。所以 `poses()` 必须覆盖运动：若手势越出采样范围，审计的 `unseparated` 行会点名该对（"framed plane: … add it to poses()"）。
- 保持范围物理且小：三节手指每关节 ±5° 看起来已是活动中的手；每关节 20° 则每条路线与每个接触都需重新证明。
- **铰接连杆上的路线承袭连杆的俯仰范围。** 第 5 节的 `endon` 规则与弯折界限用的都是线能达到的倾角，而非静止倾角：R = 8.6r 的水平 90° 弯折（在平面的 8r 规则之内）放在 ±12° 铰链上会过不了 `folds` 与 `self`，因为在 12° 俯仰下它需要 21r。让线直通接线盒，或把弯折挪到父组。

## 9. 绘制顺序及其为何正确

每对可能在屏幕上重叠的部件获得一种关系：固定在共享组内的平面（planar）、固定在共同祖先坐标系中的平面（framed）、每帧的 GJK 平面（dynamic，彼此相对运动的组）、或跳过（同一条路线的相邻块）。在该坐标系中 n·V > 0 时 B 在 A 前面。顺序是以上一帧顺序为键的稳定 Kahn 拓扑排序；遇到僵局时，删除屏幕精确包络相离（或在 0.1 px 内相触）的部件之间的边；残留僵局则强制抉择一次，由审计计数并定为致命。

之所以正确：两个投影重叠的不相交凸体必被某条视线同时命中，而分离平面恰好穿过这条视线一次。之所以无闪烁：平面关系只在平面侧对视线时翻转，而那一刻两个足迹分居一条线两侧，交换它们不改变任何像素。侧对关系（|n·V| < 1e-7）不加边。

## 10. 着色与淡出

- 平直面（棱柱侧面、端帽、球 flat）通过平滑阶梯使用套件的阈值（直立棱柱用 `EB`，其余用 `LB`）：面保持套件色调，除非落在阈值 ±0.035 之内，那里按每带 64 步交叉渐变（`data-q`，0…256）。这一细步保持 chrome 高对比色带的平滑。
- **continuity 检查行测的是未取整的几何。** 页面写入的路径坐标取整到 0.01 px，最多移动一条边 0.005 px，远小于一个设备像素。在取整路径上测量时，长边的取整阶梯永不缩小，因此二分检验曾把大平直面（示例中的掌面、桌面风扇 21 高的棱柱臂）误读为并不存在的跳变。所以 `orbit` 会为 continuity 检查行把运行时切到精确坐标（`TURN.exact(true)`），之后切回；转动组上的大平直面没有问题。
- 曲面总是用解析等照度带（`labelledArcs`），从不用面片。胶囊 dome 是嵌套包络；带 flats 的球是被裁剪的盖帽。色带诞生时宽度为零。
- 淡出线槽承载 ribs 与 bevels：alpha 量化到 1/32，槽的数量取构建期环视扫掠（orbit sweep）显示该组所需的数量。
- `lit: true` 使用 lit 令牌；带材质时用该材质的 lit 集。

## 11. 静态层与转台周围的杂乱车间

每个静态项携带 `layer`（`R.put({ …, layer: "back" })`），构建会按第一条成立的规则，在所有可达状态上证明它与每个活动层的恒定关系：**水平平面**（项完全在层的 z 范围之下或之上）、**圆柱规则**（项沿视图地面方向完全位于转动组扫掠圆柱之后或之前）、屏幕上**永不重叠**、或**扫掠包络平面**。否则：`static S interleaves live layer Λ: split S at z = …, or move it`。

密集车间的创作规则（`examples/turning-dial/stress.mjs` 证明了 450 个关系：工作台、转台底座、电源单元、工具架、缆线卷盘、托盘、扳手、三条台面缆线）：
- **让杂物在扫掠圆柱之外或转台平面之下。** 高物（电源单元、工具架、灯）沿视图地面方向 (cos a, sin a) 放在半径 R（活动层离轴的伸展距离）圆柱的后方或前方。位于其侧旁、既不在后也不在前的东西必须矮。
- **转台最低活动 z 之下的任何东西都在活动层后面，即使它在台面上位于前方。** 它属于活动层之下的层（`back`），而非 `front`：构建会这么说。
- **必须到达转动部件的缆**在台面上走到固定底座，在其内部攀爬，经轮毂处的滑环或旋转接头到达转动部件。静态段画到底座上的一个端口，活动缆从转动转盘上的接线端子排出发。没有任何路线跨越静止地面与转动组。
- 静态缆平贴台面（弯折在台面平面内，R ≥ 8r）因此永不折褶，并终止于端口、卷盘或标记为 `free` 的自由端。搭在台面上的缆（中心在台面顶 + r）会触碰台面，套件的 `clearance` 检查会判失败（`close stand.feed × stand.bench clearance 0.00 < 0.40`），除非路线声明如此：`R.route(name, route, r, { owner: name, limp: true, touch: ["stand.bench"] })`。
- `stress.mjs` 是性能与层证明场景，不是审计干净的场景：它的台面缆没有 `touch`、它的手有松脱连杆，所以套件审计过不了它。创作模式请从 `build.mjs` 复制。

## 12. 跟随转动与各组的着色器

`kit/gl.mjs` 新增（两者皆需选择启用；旧片元感知不到任何新增）：
- `GLSL_TURN`：`uGroupX/Y/Z/T`、`toGroup(p)`、`toWorld(g)`、`dirToGroup(d)`、`dirToWorld(d)`，以及遮罩 `uCoverEdge[60]`、`uCoverCount[6]`、`coverOf(vb, soft)`。
- `glslPose(Name, prefix = "uName")`：同样四个函数适用于任意组（`toDial`、`fromDial`、`dirToDial`、`dirFromDial`），使一个着色器可跟随多个组。
- `glLayer` 按声明类型把长度大于 4 的数组送入 `vec2`/`vec3`/`vec4` uniform 数组（float 数组不变）。

着色器如何跟随运动：
1. **运动部件上的内容**（指尖上的 LED、破裂管口喷出的火焰、管端喷油）：每帧用 `controller.anchor(group, restPoint, restDir)` 取锚点，把 `world`、`screen`、`direction` 作为 uniform 传入。把它画在**前画布**上（活动层之上），并用在它之后绘制的部件遮挡它：`const c = TURN.cover(controller, [partName]); layer.draw({ ...c, … })` 以及 `ink *= 1. - coverOf(vb, .7 * px)`。每个活动部件都是凸的，所以其包络就是精确剪影；遮罩外扩 0.3 vb，墨水止于遮挡物的描边，绝不进入其内。多个目标共享六个多边形：`TURN.cover(controller, [["hand.f2.p3"], ["hand.pod.socket"]])`。
2. **固定在转动表面上的内容**（转台上汇聚的油、光在刻度盘上显现的纹理）：传入 `TURN.poseUniforms(controller, "dial", "uDial")`，在静止世界坐标中求值：`vec3 q = toDial(onFloor(vb, FACE_Z));` 油池随刻度盘转动。
3. **世界空间中的内容**（升起的烟、离开源之后的火花、转台之外台面上汇聚的油）：绝不触碰组变换。粒子诞生时从锚点的世界位置发射，在世界空间中积分（示例的火花）：转动不会拖拽它们。
4. **后画布**（光落在被部件覆盖的表面之下）：把画布放在两个活动层之间。示例把刻度盘拆成自己的活动层 `dial`，置于 `hand` 之下，LED 光池落在盘面上，手把它盖住，完全不用遮罩。

`webgl.md` 的每条规则仍然成立：包络、任何绑定之前窗口归 0、浅色主题墨水（饱和主体、淡核心、着色地面、墨只随光增长）、抖动、画布边缘为 0、SVG 回退（放在所属部件内的 `T.billboard`，藏于 `[data-gl]` 之下，以 `(1 − u)/(1 − u·α)` 交接）。遮罩块占用 70 个 uniform 向量：读取 `MAX_FRAGMENT_UNIFORM_VECTORS`，并把 SVG 回退保持在 128 以下。`GLSL_TURN` 定义了 `toWorld`：不要把它前缀拼到自带定义的片元上。

## 13. 环视审计（orbit audit）

`node build.mjs --audit` 先跑套件审计，再跑 `TA.orbitOrExit(T, R, P, options)`，它每项检查打印一行，以 `turn audit passed` 或 `turn audit failed: n problems`（退出码 1）结束。只有完整运行才会以 `turn audit passed` 结束：带 `only` 的运行以 `turn audit partial: no problems in what ran (n lines skipped by only)` 结束，快速运行以 `turn audit quick: no problems in what ran (quick run, undersampled: the full run is the proof)` 结束。

选项：`sweep: { at(x), from, to, frame }`（转动）、`clips: [{ name, at(t), from, to, frame }]`（手势、断裂分离：60 fps 的每一帧）、`poses`（额外状态）、`crowd: [[route, part]…]`（经你查看后豁免 `crowding` 的对）、`cover`、`fittings: [[route, from, to]]`（管件内的区段，豁免 `endon`）、`quick`（状态数约少 10 倍，用于迭代）、`only: ["order", "rigid", "swept", "posed", "routes", "coverage", "continuity", "depth"]`（未知名字会抛错）、`log`。示例接受 `--quick`、`--only=a,b` 与 `--verbose`。`only` 会运行这些行：`order` → `unseparated`、`cycles`、`forced`、`swaps`；`routes` → `folds`、`self`、`crowding`、`endon`；`depth` → `depth`、`layers`；其余各运行自己的行。`separation` 总是运行。未运行的行打印 `skipped`。

**耗时与迭代方式。** 环视审计很慢，耗时随部件数 × 状态数增长。在 28 部件的桌面风扇（一个转动、一个铰链、一个片段）上实测：`--quick` 85 秒，完整运行 17 分钟。示例场景要数分钟；完整运行按每部件约 30–40 秒做预算。这会超过 shell 的 10 分钟超时，所以：
1. 对你正在修的行用 `--quick --only=…` 迭代。
2. 最终运行前先单独跑 `--quick`。它采样不足：它检查了 100 个二分候选，而完整运行检查 800 个，漏掉了完整运行发现的 20 个 `continuity` 失败。
3. 最终完整运行放后台（`node build.mjs --audit > audit.txt 2>&1 &`），结束后读取。只有那次运行的 `turn audit passed` 才算数。

| 检查行 | 判失败的情形 | 修法 |
|---|---|---|
| `separation` | 同组部件对没有平面（余量 < −0.08） | 拆分、加 flat、或改成齐平接触 |
| `unseparated` | 跨组部件对在包络重叠时互相穿透；被某个状态破坏的 framed 平面 | 修接触或运动；把该运动加入 `poses()` |
| `cycles` | 某状态下重叠部件之间成环；打印部件、状态范围与分裂平面（余量最大的环边） | 用 `T.split` 在该平面切开该部件 |
| `forced` | 运行时不得不强制抉择 | 同 cycles |
| `swaps` | 两个重叠部件在重叠超过 0.25 px² 时交换顺序（构建时齐平、余量小于 0.05 的对为 0.5 px²：在其接触平面侧对视线的瞬间，真实重叠是一条线，绘制的曲线会留下约 0.1 px 宽的细条） | 先查看：`drive.mjs page.html '[["orbit", "swap.png", θ−0.3, θ+0.2, 0.1, null, 6, [x, y, w, h]]]'`（θ 取自该行；区域为该对周边、以图版的 CSS px 计、缩放 6）。一步之内出现或消失的东西是绘制 bug，不是顺序 bug。2026-10-06 之前的引擎在绘制带单个 `"dome"` 端且短于其半径的 round 时，会在 flat 端后面多画一个楔形，当该端侧对视线时楔形消失：复制当前的 `turn.mjs`。若交换发生时两侧顺序（`__isoTurn.order`）都正常，则是一个错误的平面：连同部件对与 θ 一起上报 |
| `layers` | 静态项落在活动部件错误的一侧（射线投射） | 移动或拆分它（第 11 节） |
| `rigid` | 套件间隙、端子、支撑、静止时的实体间隙 | 同套件审计。铰接组的每个部件都报 `support loose`：组内没有任何东西接触父组（铰节盘，第 5 节）。`terminal … from X`：路线从端口表面而非安装面出发（`T.tube` 行，第 4 节）。`clearance … × stand.bench`：台面缆没有 `touch`（第 11 节） |
| `swept` | 静态形状落在转动组的扫掠包络之内 | 把它移出圆柱 |
| `posed` | 不同组的形状（以及运动活动 × 静态）在任一采样状态下互相穿过 | 修运动或几何 |
| `folds`、`self`、`endon` | 活动路线在每个角度与姿态下 | 第 5 节（含俯仰范围的弯折半径，第 8 节） |
| `crowding` | 活动路线的端点或弯折在某角度落到细长实体（杆、柱、茎）的轮廓上 | 与转动杆平行的线无论偏移多少都会在某角度穿过杆的轮廓，无法设计掉。查看它给出的角度（`["turn", θ]` 与 4 倍截图），若读起来是两个独立部件，把该对列入 `crowd: [["cable.a", "yaw.stem"]]`，或让线走杆的内部。不平行的线：让它以跨过杆的方式接近 |
| `coverage` | 部件记录的形状覆盖其绘制不足 60% | 记录真实形状 |
| `depth` | 射线投射预言机与引擎顺序不一致 | 上报 |
| `continuity` | 每 0.05°：色调阶跃 > 1/16 色带、一次诞生 > 2 px²、dot 的 α 阶跃 > 0.01、淡出 α 阶跃 > 1/32 + 0.005、轮廓运动超过 1.5·ω·Δθ + 0.05 px；以及二分检验 | 会中途停住的细节：让它淡出。轮廓或面边界在一步内跳变的部件：用 0.1° 的环视图找出角度；若是普通套件基元出现此况则为引擎 bug，连同部件与 θ 上报。`--quick` 采样不足：只有完整运行才算数 |

二分检验把每个候选阶跃按其自身的 ½、¼、⅛ 重新发射（用精确坐标），以 4× 栅格化各帧（8 条子扫描线上的抖动采样），测量改变归属的像素并按色调加权。平滑变化随步长减半而减半；跳变不会。若某阶跃在每次减半后都保持在 60% 以上、且在 ⅛ 处仍 ≥ 2 tone·px²，即为不连续；以 4× 测量后再以 16× 复测：4× 下失败的阶跃，只有在 16× 下也失败才算失败。若改在页面的取整路径上测量，每条长边都保有一个约为其长度 × 0.01 px 且永不缩小的下限；切换到精确坐标之前，正是这个下限把大平直面标记了出来。每条检查行都有一个专使它失败的植入故障（构建会话中的 `3d/engine/plants.mjs`：一块沉入的垫块、三根斜棍组成的风车、竖直平面内的纤维弯折、一根 30° 的管、一行停住的 rib）。

## 14. 浏览器检查

```sh
node examples/turning-dial/build.mjs --light --verify           # writes turning-dial-verify-light.html
node scripts/turn-check.mjs examples/turning-dial/build.mjs --fidelity
node scripts/turn-check.mjs page-verify.html --order --step 1
node scripts/turn-check.mjs page-verify.html --order --states clip.json
node scripts/turn-check.mjs page.html --pops --no-webgl --step 1 --out shots/pops
node scripts/turn-check.mjs page.html --lines                    # and the dark page
node scripts/turn-check.mjs page.html --perf --width 1440
node scripts/turn-check.mjs page.html --perf --width 390 --throttle 4
node scripts/turn-bench.mjs examples/turning-dial/build.mjs
node scripts/drive.mjs page.html '[["turn", 37], ["shot", "a.png"], ["orbit", "orbit.png", 0, 345, 15]]'
```
- `--fidelity`（Node）：prism 对照 `k.extrude`/`G.prismOf`（轮廓、顶面与侧面各 ≤ 0.06 px）；round 与 lathe 对照 `G.lathe(…, smooth)`（轮廓对以 10× 绘制的套件 ≤ 0.05 px，色带 ≤ 0.5 px；该行还会打印对照套件自身路径的轮廓，套件路径取整到 0.1 px，故那里的 0.08–0.13 px 属预期、不予判定）；tube 对照 `tubePieces`（0.05 px）；均在 P′(θ) 处。对照（control）：故意偏画 2° 的 prism 必须失败。
- `--order`：把记录的形状放进 WebGL z 缓冲，对照 DOM 绘制器的填充，2×；活动对有 4 个以上内部像素即失败。对照：每个活动层反转后须给出 ≥ 1000 px。静态 × 活动的不匹配会列出（静态记录形状常是替身，例如用一块实心板代替带窗的板）。`--part name` 打印某部件在两图中的足迹。`--step` **只扫掠第一个转动组**，其余组全部静止：铰链、平移或片段需要 `--states`。
- `--pops`：一阶差分（θ → θ + 0.02°，两次腐蚀）与二阶差分（0.1°，|2b − a − c| > 56，平直像素上 > 6，一次腐蚀；核达 6 px 即失败）。对照：把最大的部件隐藏一帧。`--out dir` 保存第一个核的各帧。配 `--states` 时，相邻条目视为相邻帧，只运行一阶差分，因此列表必须是**以约 0.02° 步长构成的一条连续路径**：529 个互不相关的 yaw × tilt 姿态给出 404 个误报；以 0.02° 扫掠 1201 个状态的 tilt 路径给出 0。
- `--states file.json`：以值对象列表代替角度。从构建模块写出这些列表，模块导出 `follow` 与各片段函数：
  ```js
  import { writeFileSync } from "node:fs";
  import { follow, nodAt } from "./build.mjs";
  const at = (t) => follow({ yaw: 20 + 30 * t, tilt: nodAt(t) });
  writeFileSync("clip.json", JSON.stringify(Array.from({ length: 241 }, (_, i) => at(i / 60))));
  writeFileSync("tilt-path.json", JSON.stringify(Array.from({ length: 1201 }, (_, i) => follow({ yaw: 30, tilt: -12 + i * 0.02 }))));
  ```
  `clip.json`（片段的每个 60 fps 帧）用于 `--order`；`tilt-path.json`（单个铰链按 0.02° 扫掠）用于 `--pops`。每个铰链跑一条路径的 `--pops`，转角选在铰链部件重叠最大的位置。

## 15. 性能

由 `turn-bench`（Node CPU）与 `turn-check --perf`（浏览器，1.1° 步长 240 帧）测量。

**一个部件的代价。** `turn-bench` 按种类打印每个部件的 Node 时间。以 prism 单位计（一个活动 prism，在构建机上约 0.03–0.04 ms/帧）：

| 种类 | 代价 | 种类 | 代价 |
|---|---|---|---|
| `fixed`（竖直 round、普通 ball） | 0.5 | `round` | 2.5–4 |
| `prism` | 1 | 带 flats 的 `ball` | 8–10 |
| tube 块 | 2–3 | `lathe` | 约 25 |

一张图的重量是各部件之和。**小图**重至约 50（几十个部件，多为 prism 与 fixed 画面）；**密集**图至约 230。桌面风扇（28 部件：6 prism、7 fixed、5 tube 块、8 round、2 带 flats 的 ball）重约 65，实测每帧 1.6–1.9 ms Node CPU、1440 下浏览器任务 6.0 ms，所以已越过小图线，主要因为那两个球。转动刻度盘（88 部件、42 round、一个 lathe）重约 225，实测 6.4–7.2 ms。带 flats 的 ball 是"带 dome 端且有边缘落在其上"场景的正确部件（第 5 节），但代价相当于九个 prism；普通 ball 或竖直 round 是 fixed 画面，几乎免费。时间随机器与负载而变：种类对比请在同一次运行内进行，并实测你自己的图。

| 指标 | 小图预算（重量 ≤ 50） | 密集图预算（重量 ≤ 230） |
|---|---|---|
| 每帧 Node CPU | ≤ 2 ms | ≤ 7 ms |
| 浏览器主线程任务（1440，DPR 2） | ≤ 6 ms | ≤ 13 ms（60 fps） |
| 主线程（390，DPR 3，4× CPU） | ≤ 16 ms | ≤ 33 ms（30 fps） |
| `data.turn` JSON | | ≤ 250 KB |

杠杆，按优先级：
1. 每个竖直轴转动部件与每个普通球都用 `fixed`（自动）。
2. 面上的每组线或文本都用 plane；直立棱柱顶面是一个矩阵。
3. 小部件按设备像素采样：不足 30 px 的 round 部件，其 rings、caps 与 domes 取 12–16 个采样，绝不用大部件的最小值。
4. **framed 平面与相对姿态缓存**（自动）：组保持相对姿态期间（纯转台转动），跨组对零成本；构建采样过其运动的对即 framed 平面。
5. **自适应半速率**（图的循环）：维护 `controller.set(...)` 时间的指数移动平均；高于 14 ms 时隔帧渲染活动层（基于时间的运动不变），低于 9 ms 时恢复每帧（`stress.mjs` 的循环）。
6. **按速度调节细节**（需选择加入）：`controller.set(values, { detail })`，`detail = settle(1 − smoothstep(120, 240, |ω|°/s), 0.25 s)`：淡出的线、ribs 与 dots 随之缩放，低于 0.01 时跳过。轮廓与色调绝不降低。

让图保持在预算内的创作规则：每个运动组约 150–250 个活动部件；小细节作为 `details`（dots、rings、bolts）而非部件；静态杂物作为静态图；每个独立运动区域一个活动层；tube 按 6 分块且块数压到弯折允许的最低。示例与压力场景的实测数字在 skill 的构建笔记中；在本机上，380 部件的弯曲手指借助半速率杠杆是 1440 下 30 fps 的图，不是 60 fps。

## 16. 已知限制

- 竖直转轴走方位角捷径；其他旋转做矩阵合成。
- 只有凸部件。凹体由凸件组成；ball flats 取代边缘落球面的关节。
- 活动 tube 遵守折褶与端向规则：没有扫掠管剪影，所以转向只在近水平或管件内发生，且没有路线跨越两个运动组。
- 无自动拆分：环是一次带建议平面的审计失败。
- 平直面在分值 ±0.035 内交叉渐变（约合 8° 的转动）。
- lathe 在色带改变拓扑处保留小残余台阶。
- 自由组在运行时与整层配对；几十块碎片在运动期间产生 GJK 开销。
- 手机：预算瞄准 30 fps 而非 60，且只有落在预算内的图才能达到。380 部件的压力场景（`examples/turning-dial/stress.mjs`）在重载机器上、带半速率杠杆，实测 1440 下约 20 fps、390 带 4× CPU 节流下 13–15 fps。没有 canvas 绘制器。
